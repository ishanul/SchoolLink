# Task: Requirements and Workflows

## Goal

Turn the project idea into clear requirements and user workflows.

The goal is not to write many vague requirements. The goal is to write requirements that another developer could understand, build, and test.

## User Stories

Write user stories for the main workflows.

Use this format:

```text
As a [user role],
I want to [perform an action],
so that [benefit or reason].
```

Example:

```text
As a parent,
I want to see important school updates related to my child,
so that I do not miss urgent information.
```

## Functional Requirements

Write functional requirements using IDs such as `FR-001`, `FR-002`, and so on.

For each requirement, include:

- Requirement ID
- Title
- Description
- User role
- Priority
- Acceptance criteria

## Non-Functional Requirements

Think about qualities the system should have, such as:

- Ease of use
- Performance
- Privacy
- Security
- Reliability
- Maintainability
- Language support

## User Journeys

Draw or describe the most important flows in the system.

For each journey, include:

- User goal
- Starting point
- Main steps
- Successful outcome
- Possible error or edge cases

## Expected Output

- User stories
- Functional requirements
- Non-functional requirements
- Main user journey diagrams or step-by-step flows
- Draft SRS using `docs/srs/srs-template.md`
