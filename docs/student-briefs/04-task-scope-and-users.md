# Task: Scope, Users, and Permissions

## Goal

Decide what the first version of the platform should solve, who it is for, and what each user should be allowed to do.

The first version should be realistic for a student group to design and build.

## Work To Complete

Define the MVP.

Your group should decide:

- What problems should the first version solve?
- What problems should be postponed?
- Which users are essential for the first version?
- Which users or features can wait?
- What makes a feature important enough for the MVP?

Important:

The MVP does not need to include every good idea. A smaller, clearer version is better than a large unclear version.

## User Roles

Identify the user roles required for your proposed system.

For each role, explain:

- Who the user is
- What they need from the platform
- What actions they should be allowed to perform
- What information they should not be allowed to access

## Permissions

Create a permission matrix.

Think carefully about privacy and responsibility. For example:

- Who can create official school notices?
- Who can create class-level updates?
- Who can view information about a student?
- Who can respond on behalf of a student?
- Who can manage users and school records?

## Expected Output

- MVP feature list
- Out-of-scope feature list
- Short reason for each decision
- User role descriptions
- Permission matrix
- Questions or assumptions that need mentor feedback
