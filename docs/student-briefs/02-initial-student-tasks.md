# Initial Student Tasks

These tasks are for one student group of five members.

The first goal is not to start coding. The first goal is to understand the problem, define a realistic first version, and explain the thinking clearly.

Use SchoolLink as the working name for now. The group may keep it or propose a better name during discovery.

## Task Files

Complete the work in phases:

1. [Discovery and Problem Understanding](03-task-discovery.md)
2. [Scope, Users, and Permissions](04-task-scope-and-users.md)
3. [Requirements and Workflows](05-task-requirements-and-workflows.md)
4. [Data Model and Wireframes](06-task-design-artifacts.md)
5. [Presentation and First Review](07-task-presentation.md)

## Suggested Team Split

- Student 1: Problem research and user pain points
- Student 2: User roles, permissions, and user stories
- Student 3: Functional and non-functional requirements
- Student 4: Data model and user journeys
- Student 5: Wireframes, presentation, and product naming

Students should still review each other's work. The final submission should feel like one coherent product proposal, not five disconnected documents.

## First Check-In Submission

For the first check-in, submit only:

- Problem analysis document
- Product name options and recommendation
- Initial MVP and out-of-scope list
- Initial user role list
- Questions or assumptions that need mentor feedback

The SRS, data model, user journeys, and wireframes can be improved after the first feedback session.
